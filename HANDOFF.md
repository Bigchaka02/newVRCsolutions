# Handoff: adopting the v2 front end and wiring up the backend

Notes for whoever takes this repo next. Read this together with `README.md`,
which covers running, deploying and editing content. This file is about what
is unfinished, what is uncertain, and the details that are easy to break.

---

## 1. What you are looking at

| Branch | What it is | Preview |
|---|---|---|
| `redesign` | **v2, the version to adopt.** The replica plus the motion/visual layer, dark product cards, sticky discount bar, minified build. | https://bigchaka02.github.io/newVRCsolutions/v2/ |

Both previews are static GitHub Pages builds with **no API behind them**, so
checkout, contact and order lookup show "This site isn't connected to its
server yet". That message is expected there, not a bug.

The v2 page structure, section order, copy and colour palette are deliberately
the same as the live site. Treat them as settled unless the owner says
otherwise.

## 2. Ground rules

- **Never invent lab data.** Every purity figure, lot number, test method,
  test date, molecular weight and COA link is a claim about a real certificate.
  If it isn't confirmed, it stays in that product's `review` list and the page
  shows the conservative wording (for example "≥99%" and "Not published").
- **No dosing, reconstitution, protocol or human-use content anywhere.** Not in
  copy, alt text, FAQs, emails or structured data. Everything is sold for
  research use only (RUO); the gate, checkout confirmation and policy pages
  enforce that.
- **Authorship:** commits are authored as `Bigchaka02`. Don't add tool or AI
  credits, co-author trailers or "generated by" notes to code, commits or pages.
- Leave `main` alone until the owner decides to promote v2.

## 3. Adopting v2

1. Merge `redesign` into `main`, or ask the owner to fast-forward `main` to it.
2. On `main`, simplify `.github/workflows/pages.yml`: delete the "Look for the
   redesign branch" / "Build the redesign at /v2/" steps. Then delete
   `.github/workflows/preview-redesign.yml`, which exists only so pushes to
   `redesign` republish the /v2/ preview.
3. For the real domain, build without a base path: `python3 build.py`. The
   `--base-path` flag exists only for the GitHub Pages sub-folder and forces
   `noindex` on every page.
4. Run `python3 build.py --strict` before launch. It refuses to build while any
   product has open `review` items, and at the time of writing all 23 do (see §6).

## 4. How the front end talks to the backend

All browser calls go through `src/assets/js/api.js`.

- **API base:** set by `site.api_base` in `data/products.json`. The build writes
  it into `<meta name="vrc-api">`. Empty means same origin (`/api/...`); that
  is the one-container Docker setup, where the API also serves `public/`.
- **Separate API host:** set `site.api_base` to its origin, rebuild, and add
  the site's origin to `CORS_ORIGINS` in the backend `.env`. `build.py` adds
  the API origin to the CSP's `connect-src` automatically.
- **Errors:** FastAPI error bodies are turned into one readable sentence
  (`readError()`); a 404/405/501 with no JSON body is taken to mean "no API
  here".

| Browser call | Called from | Backend route |
|---|---|---|
| `POST /api/cart/price` | checkout summary (`checkout.js`) | `routers/catalog.py` |
| `POST /api/orders` | checkout submit (`checkout.js`) | `routers/orders.py` |
| `GET /api/orders/{ref}?email=` | `/order-status/` (`checkout.js`) | `routers/orders.py` |
| `POST /api/compliance/ruo-ack` | RUO gate "Enter" (`ui.js`, fire-and-forget) | `routers/compliance.py` |
| `POST /api/contact` | contact form, via `data-api` on the form (`ui.js` `initForms`) | `routers/contact.py` |

Not called by the storefront but available: `GET /api/products`,
`GET /api/products/{slug}`, `GET /api/coas`, `GET /api/health`, the admin
routes, and `POST /api/webhooks/{card|crypto|shipping}`. Product pages and the
COA library are pre-rendered from `data/products.json`, not fetched.

- **Prices are authoritative on the server.** The cart total in the browser
  (`store.js`) is a preview only; `POST /api/orders` reprices everything from
  the database. Keep it that way.
- **Keep the catalog in step.** The database is seeded from
  `data/products.json` (`python -m app.seed`, which upserts). An admin COA
  change (`PATCH /api/admin/products/{sku}/coa`) updates the database only;
  mirror it in the JSON and rebuild, or the pages and the API will disagree.

### Pricing rules live in four places

The authoritative values are in `backend/app/config.py`: free shipping over
$105, flat shipping $9.95, promo `FIRST15` = 15%. They are repeated in:

1. `src/assets/js/store.js` → `CONFIG` (cart preview)
2. `src/layout.html` → the green discount bar text
3. `src/product.html` → the perks list under "Add to cart"

Change all four together.

## 7. Other uncertainties

- **Email addresses:** `hello@` is used for general contact and `support@` for
  orders. `compliance@`, `privacy@` and `legal@` also appear in `site` and the
  policy pages. Confirm which inboxes actually exist.
- **Legal pages** (terms, refund, privacy, RUO) were copied from the live site
  and need a legal review. The live Terms' "International Orders" and "Customs
  Duties and VAT" sections were left out because checkout is US-only.
- **Operational claims** in the copy come from the live site: "next-day US
  shipping", "orders before 2pm ET ship next business day", "real US LLC",
  "≥99% purity cutoff". Keep them true or change them.
- **Home page photos** (`public/assets/img/why/`) are Unsplash images (free
  licence), not VRC's own. Swap in real photos if you have them.
- **Accessibility trade-off (owner's decision):** the looping background
  animations have no pause button; the owner asked for them to be removed. That
  misses WCAG 2.2.2 (Pause, Stop, Hide). Visitors whose system asks for reduced
  motion still get a slower, smaller version (see §8). If an accessibility
  audit matters, raise it with the owner before re-adding a control.
- **v1 only:** on `main`, the privacy policy links to `/terms-of-service/`,
  which 404s on GitHub Pages (the redirect only works on hosts that read
  `_redirects`). It is fixed on v2; it disappears once v2 is adopted.

## 8. Front-end notes and gotchas (v2)

**Build**

- Edit `src/` and `data/`, never `public/`. `public/` is committed build output.
- `python3 build.py` minifies HTML, joins and minifies
  `tokens.css + vrc.css + fx.css` into `public/assets/css/site.css`, minifies
  each JS module, and stamps every asset URL with `?v=<content hash>`.
- `minify.py` is deliberately conservative (no renaming). If you ever suspect
  it, compare a minified module against its source by parsing both.

**Where the code lives**

- **Base design:** `src/assets/css/vrc.css`.
- **v2 visual layer:** `src/assets/css/fx.css`, `src/assets/js/fx.js` and
  `src/assets/js/motion.js`. Features: glow stages with particles, levitating
  vials, page transitions, card tilt, magnetic buttons, scroll reveals and the
  add-to-cart effects.

**Content Security Policy**

- The CSP is first-party only and allows **no inline scripts**. That is why
  `motion.js` is a separate file loaded in `<head>`.
- It must stay a *classic, render-blocking* script: it sets
  `<html data-motion>` before first paint and registers the
  `pageswap`/`pagereveal` handlers the page transitions need.

**Motion levels**

- `data-motion="full"` is the default.
- `calm` applies when the OS asks for reduced motion (Windows "Animation
  effects" off, macOS "Reduce motion"). It keeps the same effects, slower and
  smaller, with no tilt, magnet or sliding. The owner wanted effects visible on
  such machines; don't switch them off entirely for `reduce`.
- There is no `off` level any more. `motion.js` clears an old
  `localStorage['vrc.motion']` left by the removed pause button.

**Animation rule**

- Only clickable things react to hover (buttons, product cards, the hero vial
  link, COA links). The owner was explicit: no hover effects on static cards,
  icons or circles.
- Ambient motion lives only on `.fx-glow` stages.

**Product cards**

- `card()` in `build.py` renders every card as a dark glass card (`pcard-show`)
  when a cut-out exists.
- In the shop, `pcard-solid` adds its own teal background because the page
  behind it is cream.
- A product **without** a cut-out falls back to the plain white card, which
  will look out of place. Make one with `tools/make_cutouts.py`.

**Page transitions** (`@view-transition` in `fx.css`, naming in `motion.js`)

- A product's vial morphs from the clicked card into the product page.
- Only one element per page may hold `view-transition-name: product-vial` at a
  time, or the transition is skipped.
- `.topbar` and `.site-header` carry fixed names so they stay put during
  navigation.
- Shop filtering uses a same-document view transition (`glide()` in `ui.js`).
  Search typing deliberately doesn't, because a view transition freezes the
  page, including the text box.

**Sticky discount bar and header**

- The discount bar (`.topbar`) and header are both sticky; the header sits at
  `top: var(--topbar-h)`.
- `ui.js` measures the bar with a ResizeObserver because its text wraps on
  phones.
- `scroll-padding-top` and the sticky `.coa-card` / `.summary-card` include
  `--topbar-h`. Use the same variable for anything new that sticks.

**Layering (z-index)**

- Header 50, discount bar 51, back-to-top 55, drawer 60/61, gate 90, toast 95.
- The gate and drawer must stay above the bar.

**Browser support**

- View transitions: Chrome/Edge/Safari. Firefox just loads pages normally.
- Scroll-driven parallax is behind `@supports (animation-timeline: view())`.
- The particle canvases pause when off-screen or when the tab is hidden.

## 9. Testing

```bash
python3 build.py && (cd backend && python -m pytest -q)        # 26 API tests

# Browser checks (need Node and Playwright: npm i -D playwright && npx playwright install chromium)
python3 -m http.server 8080 -d public &                        # or run the API with SERVE_STATIC=true
BASE=http://localhost:8080 node tests/browser/crawl.mjs         # every page: links, images, JS errors, sideways scroll
BASE=http://localhost:8080 node tests/browser/checks.mjs        # gate, shop, cart, promo, search, anchors, phone menu, checkout
```

- **Sub-path builds:** for a GitHub Pages-style build
  (`--base-path /newVRCsolutions`), serve the parent folder and point `BASE`
  at `http://localhost:8080/newVRCsolutions`.
- **Checkout check:** with the API running it expects a `VRC-…` order
  reference; without it, the "isn't connected" message. Either passes.
- **State at handoff:** both scripts pass at the site root and under the
  base path. The API tests pass 26/26, and `--strict` fails on the open
  catalog items in §6, as intended.
